# Synthetic test POs (30 files: 3 per retailer)

**Test data only: these are not real orders.** Every page carries the footer "DỮ LIỆU TỔNG HỢP ĐỂ KIỂM THỬ".
Generated by `scripts/make_synthetic_po.py` (fixed seed, reproducible). The layouts copy each retailer's real PO
(or, for Lan Chi, the Excel screenshot), with other values: products from Bibica's catalogue, store codes from
the DMS Excel, other dates, line counts and number formats.

- `pdf/<RETAILER>_synth_<n>.pdf`: the POs
- `gt/<same stem>.json`: ground truth in the same format as `data/po_gt/` (`"synthetic": true`)

## What each file stresses
| Retailer | File 1 | File 2 | File 3 |
|---|---|---|---|
| AEON (image only) | 4 lines | 11 lines, rotated 0.6° | 17 lines on 2 pages, rotated + noise + JPEG; delivery date in the next year |
| BHX | 3 lines | 9 lines on 2 pages; **internal code 105… on the top line** (2021 layout) | 16 lines, 3 pages; date range across months |
| BigC | 6 lines + 1 store-split page | 22 lines + 3 store-split pages; Order Date 03/04/24 (day/month ambiguous) | 45 lines on 2 PURCHASE NOTE pages + 4 store-split pages; +5 days crosses the year |
| COOP | 5 lines | 14 lines | 31 lines on 2 pages; date 30/12 |
| E-Mart | 2 lines, Gò Vấp (DMS 7120) | 8 lines, other store (code not in the DMS Excel) | 19 lines, other store |
| Lotte | 01013 (Nha Trang) | 01004 (Đà Nẵng) | 01015, 24 lines on 2 pages |
| MM (image only) | 3 lines | 10 lines, quantities as "60,00", rotated | 22 lines, noise + JPEG, ILN not in the DMS Excel |
| SATRA | "Ngày: 4/3/2024" = 3 April (month first, ambiguous) | 6 lines | 12/29/2024 + 5 days = 2025-01-03; quantities "1,000" = 1 |
| VIN | 1 line (1324) | 7 lines (1333) | 20 lines on 2 pages (1331) |
| LANCHI | 4 lines | 10 lines | 18 lines; date 30/12 + 5 = 2025-01-04; per-store columns must not be read as quantity |

Ground-truth rules follow `config/po_customers.yaml`, notably:
- BigC, Satra and Lan Chi: printed date **+5 days**;
- BHX: delivery date = first day of the range, code = top line of the cell;
- E-Mart: Mã KH = the whole "Delivery to" text.

## Evaluate
```bash
uv run python -m bibica_rag.po.extract data/po_synth/pdf --out results/po/synth-qwen3.5-4B
```
```bash
uv run python -m bibica_rag.po.evaluate score --pred results/po/synth-qwen3.5-4B --gt data/po_synth/gt --out results/po_eval/synth-qwen3.5-4B
```
The report is written to `results/po_eval/synth-qwen3.5-4B/report.md`. It counts orders fully correct, header
fields, line precision/recall/F1 by product code, quantity accuracy, and lists every error.

## Limits
- **Same layouts as the real samples**: this measures robustness to other values, line counts, multi-page
  documents and scan quality, not to layout changes (a retailer changing its PO template). Real new POs added to
  `data/po_gt/` remain the reference.
- Cleaner than real documents (crisp fonts, no stamps or handwriting); the scans are simulated.
- Lan Chi has no real sample: its layout comes from the Excel screenshot.
- Known issue found with this data (not fixed yet): `validate.py` checks EAN-13 on every 13-digit code, so BHX
  internal codes (`105…`, also on the real 2021 screenshot) raise false "mã vạch sai số kiểm tra" warnings on
  BHX_synth_2. This affects only the warnings, not the extracted values or the score.
